# Эмулятор UNIX-подобной командной строки

Практическая работа по дисциплине
«Конфигурационное управление».

Вариант: 8.

Проект представляет собой консольный эмулятор UNIX-подобной
командной строки на языке Python.

Эмулятор поддерживает виртуальную файловую систему VFS,
загружаемую из JSON-файла.

Все операции с VFS выполняются в оперативной памяти.
Исходный JSON-файл во время работы эмулятора не изменяется.

## Требования

Для запуска необходим Python 3.

Дополнительные сторонние библиотеки не используются.

Проверить установленную версию Python:

```powershell
python --version
```

## Запуск

Обычный запуск:

```powershell
python src\main.py
```

Также можно использовать:

```powershell
.\run.bat
```

С параметрами:

```powershell
.\run.bat --vfs vfs\deep.json
```

## Параметры командной строки

Эмулятор поддерживает следующие параметры:

```text
--vfs
--prompt
--script
```

### Параметр --vfs

Позволяет указать путь к JSON-файлу виртуальной файловой системы.

Пример:

```powershell
python src\main.py --vfs vfs\deep.json
```

### Параметр --prompt

Позволяет указать собственное приглашение командной строки.

Пример:

```powershell
python src\main.py --prompt "shell> "
```

### Параметр --script

Позволяет выполнить стартовый сценарий.

Пример:

```powershell
python src\main.py --script scripts\startup.txt
```

Параметры можно использовать одновременно:

```powershell
python src\main.py --vfs vfs\deep.json --prompt "vfs> "
```

Пример запуска VFS со стартовым сценарием:

```powershell
python src\main.py --vfs vfs\deep.json --script scripts\stage4_startup.txt
```

## Этап 1. REPL

На первом этапе реализован минимальный прототип командной оболочки.

Приложение работает в консольном режиме и выводит приглашение
на основе имени пользователя и имени компьютера.

Пример:

```text
user@computer:~$
```

Реализован простой парсер команд.

Введенная строка разделяется по пробелам на:

- имя команды;
- список аргументов.

На первом этапе команды `ls` и `cd` являлись заглушками.

Также была реализована команда:

```text
exit
```

для завершения работы эмулятора.

Неизвестная команда приводит к сообщению об ошибке.

## Этап 2. Конфигурация

На втором этапе добавлена настройка эмулятора через аргументы
командной строки.

Поддерживаются:

- путь к VFS;
- пользовательское приглашение;
- путь к стартовому сценарию.

Стартовый сценарий выполняется последовательно.

На экране отображаются вводимые команды и их результат,
что имитирует диалог пользователя с командной оболочкой.

При первой ошибке выполнение стартового сценария прекращается.

Пример:

```powershell
python src\main.py --script scripts\startup.txt
```

Для проверки параметров командной строки используются BAT-файлы
из директории `scripts`.

## Этап 3. Виртуальная файловая система

На третьем этапе добавлена виртуальная файловая система VFS.

Источником VFS является JSON-файл.

После загрузки JSON преобразуется во внутреннюю структуру Python.

Все операции производятся в памяти.

Эмулятор не изменяет исходные JSON-файлы.

### Формат директории

Директория представляется следующим образом:

```json
{
  "type": "directory",
  "children": {}
}
```

### Формат файла

Обычный файл:

```json
{
  "type": "file",
  "content": "File content"
}
```

Для двоичных данных может использоваться Base64:

```json
{
  "type": "file",
  "encoding": "base64",
  "content": "AAECAwQ="
}
```

### Проверка структуры VFS

При загрузке проверяется структура виртуальной файловой системы.

Узел должен быть:

- директорией с объектом `children`;
- или файлом со строковым `content`.

При неправильной структуре выводится сообщение об ошибке.

### Ошибка отсутствующего файла

Если указанный JSON-файл не существует:

```powershell
python src\main.py --vfs vfs\missing.json
```

выводится сообщение:

```text
Error: VFS file not found: vfs\missing.json
```

### Ошибка формата

Если JSON имеет неправильный формат, эмулятор сообщает
об ошибке загрузки VFS.

### Тестовые VFS

В проекте используются три варианта виртуальной файловой системы.

#### minimal.json

Минимальная пустая VFS.

```text
/
```

#### files.json

VFS с несколькими файлами.

Пример структуры:

```text
/
├── data.bin
├── notes.txt
└── readme.txt
```

#### deep.json

VFS с несколькими уровнями директорий.

```text
/
└── home/
    └── user/
        └── documents/
            └── report.txt
```

### Скрипты проверки VFS

Минимальная VFS:

```powershell
.\scripts\test_vfs_minimal.bat
```

VFS с несколькими файлами:

```powershell
.\scripts\test_vfs_files.bat
```

Глубокая VFS:

```powershell
.\scripts\test_vfs_deep.bat
```

Проверка отсутствующего файла:

```powershell
.\scripts\test_vfs_missing.bat
```

## Этап 4. Основные команды

На четвертом этапе команды `ls` и `cd` получили настоящую
логику работы с виртуальной файловой системой.

Также реализованы команды:

```text
echo
clear
history
```

Для работы команд используется состояние оболочки.

Оно содержит:

- загруженную VFS;
- текущий путь;
- историю введенных команд.

### Команда ls

Команда `ls` отображает содержимое директории VFS.

Без аргументов:

```text
ls
```

выводится содержимое текущей директории.

Например, для корня `deep.json`:

```text
home
```

Можно передать относительный путь:

```text
ls home
```

Результат:

```text
user
```

Можно использовать абсолютный путь:

```text
ls /home/user
```

Результат:

```text
documents
```

Для файла:

```text
ls /home/user/documents/report.txt
```

выводится имя указанного файла.

Если путь отсутствует:

```text
ls missing
```

эмулятор сообщает об ошибке:

```text
Error: ls: path not found: missing
```

Команда принимает не более одного аргумента.

Например:

```text
ls one two
```

приводит к ошибке.

### Команда cd

Команда `cd` изменяет текущую директорию внутри VFS.

Пример:

```text
cd home
```

После этого команда:

```text
ls
```

покажет содержимое `/home`.

Для `deep.json`:

```text
user
```

Можно переходить последовательно:

```text
cd home
cd user
cd documents
```

Поддерживаются относительные пути:

```text
cd home/user
```

и абсолютные пути:

```text
cd /home/user/documents
```

### Переход в родительскую директорию

Используется:

```text
cd ..
```

Например, из:

```text
/home/user/documents
```

команда:

```text
cd ..
```

переведет оболочку в:

```text
/home/user
```

### Переход в корень

Используется:

```text
cd /
```

Вызов `cd` без аргументов также переводит текущий путь
в корень виртуальной файловой системы.

### Ошибки cd

Если директория отсутствует:

```text
cd missing
```

выводится:

```text
Error: cd: path not found: missing
```

Если попытаться перейти в файл:

```text
cd /home/user/documents/report.txt
```

выводится сообщение:

```text
Error: cd: not a directory: /home/user/documents/report.txt
```

### Команда echo

Команда `echo` выводит переданные аргументы.

Пример:

```text
echo hello world
```

Результат:

```text
hello world
```

Команда может быть вызвана без аргументов.

В этом случае выводится пустая строка.

### Команда clear

Команда:

```text
clear
```

очищает терминал.

На Windows используется системная команда `cls`.

На UNIX-подобных системах используется системная команда `clear`.

Команда не принимает аргументы.

Например:

```text
clear test
```

приводит к сообщению об ошибке.

### Команда history

Команда:

```text
history
```

выводит историю команд текущего сеанса.

Пример:

```text
1 ls
2 cd home
3 ls
4 echo hello
5 history
```

История хранится только в памяти и существует до завершения
текущего сеанса эмулятора.

### Работа с путями

В командах `ls` и `cd` поддерживаются:

- абсолютные пути;
- относительные пути;
- текущая директория `.`;
- родительская директория `..`;
- корневая директория `/`.

Пример относительного пути:

```text
cd home/user
```

Пример абсолютного пути:

```text
cd /home/user
```

Пример перехода назад:

```text
cd ..
```

Пример перехода в корень:

```text
cd /
```

### Стартовый сценарий этапа 4

Файл:

```text
scripts/stage4_startup.txt
```

используется для проверки команд этапа 4.

Запуск:

```powershell
python src\main.py --vfs vfs\deep.json --script scripts\stage4_startup.txt
```

Сценарий проверяет:

- `clear`;
- `ls`;
- переходы `cd`;
- просмотр файла через `ls`;
- возврат через `cd ..`;
- `echo`;
- `history`;
- обработку ошибки.

Ошибочная команда находится в конце сценария,
так как стартовый сценарий останавливается при первой ошибке.

## Основные функции

### load_vfs()

Загружает VFS из JSON-файла.

### validate_node()

Проверяет отдельный узел виртуальной файловой системы.

### validate_vfs()

Проверяет полную структуру VFS.

### create_default_vfs()

Создает пустую виртуальную файловую систему в памяти.

### create_shell_state()

Создает начальное состояние командной оболочки.

Состояние содержит:

- VFS;
- текущий путь;
- историю команд.

### normalize_path()

Преобразует абсолютный или относительный путь в нормализованный
внутренний путь VFS.

Обрабатывает:

```text
/
.
..
```

### get_node()

Ищет узел VFS по нормализованному пути.

### resolve_path()

Преобразует путь пользователя и получает соответствующий узел VFS.

### parse_arguments()

Обрабатывает параметры командной строки.

### print_configuration()

Выводит текущую конфигурацию эмулятора.

### build_prompt()

Создает приглашение командной строки.

### parse_command()

Разделяет пользовательский ввод на команду и аргументы.

### run_ls()

Реализует команду `ls`.

### run_cd()

Реализует команду `cd`.

### run_echo()

Реализует команду `echo`.

### run_clear()

Реализует команду `clear`.

### run_history()

Реализует команду `history`.

### run_exit()

Обрабатывает команду `exit`.

### execute_command()

Определяет введенную команду и вызывает соответствующий обработчик.

### execute_input()

Разбирает строку пользователя, сохраняет ее в историю
и выполняет команду.

### run_repl()

Запускает интерактивный цикл командной оболочки.

### run_script()

Выполняет команды из стартового сценария.

При первой ошибке выполнение сценария прекращается.
