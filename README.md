# Эмулятор UNIX-подобной командной строки

Практическая работа № 1 по дисциплине «Конфигурационное управление». Вариант 8.

## О проекте

Реализован консольный эмулятор командной оболочки на Python. Программа принимает команды, обрабатывает аргументы и позволяет перемещаться по виртуальной файловой системе (VFS). Поддерживаются просмотр каталогов, вывод текста, история команд и перемещение файлов.

VFS загружается из JSON-файла и хранится в памяти. Операции выполняются с виртуальными файлами и каталогами, поэтому исходный JSON и реальные файлы на компьютере не изменяются.

## Этапы работы

Работа состоит из пяти этапов:

1. **REPL.** Реализован интерактивный ввод команд, парсер с разделением по пробелам, вывод ошибок и завершение через `exit`. Команды `ls` и `cd` первоначально работали как заглушки.
2. **Конфигурация.** Добавлены параметры запуска `--vfs`, `--prompt`, `--script`. Реализовано последовательное выполнение команд из стартового скрипта с остановкой при первой ошибке.
3. **VFS.** Добавлены загрузка и проверка JSON-файла, хранение структуры в памяти, работа с вложенными каталогами и сообщения об ошибках загрузки.
4. **Основные команды.** Реализована работа `ls` и `cd` с VFS, добавлены `echo`, `clear`, `history`.
5. **Дополнительные команды.** Реализована команда `mv` для перемещения и переименования файлов и каталогов внутри VFS.

## Запуск программы

Для запуска необходим Python 3. Дополнительные библиотеки не требуются: используются стандартные модули Python. Компиляция проекта не нужна.

Все команды выполняются из корневой папки проекта.

Обычный запуск:

```powershell
python src\main.py
```

Запуск с тестовой VFS:

```powershell
python src\main.py --vfs vfs\deep.json
```

Запуск через `run.bat`:

```powershell
.\run.bat --vfs vfs\deep.json
```

### Параметры командной строки

| Параметр | Назначение |
| --- | --- |
| `--vfs` | Путь к JSON-файлу виртуальной файловой системы |
| `--prompt` | Свой текст приглашения для ввода команд |
| `--script` | Путь к текстовому файлу с командами для выполнения при запуске |

Пример запуска со всеми параметрами:

```powershell
python src\main.py --vfs vfs\deep.json --prompt "demo> " --script scripts\stage5_startup.txt
```

При запуске на экран выводятся значения параметров. Если `--prompt` не задан, приглашение формируется из настоящих имени пользователя и имени компьютера.

Если `--vfs` не указан, создаётся пустая виртуальная файловая система в памяти. При указании отсутствующего или неверного JSON-файла выводится ошибка загрузки.

## Поддерживаемые команды

| Команда | Описание | Пример |
| --- | --- | --- |
| `ls [путь]` | Показывает содержимое каталога; без пути — текущего | `ls /home/user` |
| `cd [путь]` | Меняет текущий виртуальный каталог; без пути — переход в `/` | `cd ..` |
| `echo [текст]` | Выводит переданный текст | `echo Hello` |
| `clear` | Очищает экран терминала | `clear` |
| `history` | Выводит историю команд текущего запуска | `history` |
| `mv <откуда> <куда>` | Перемещает или переименовывает файл либо каталог | `mv a.txt b.txt` |
| `exit` | Завершает эмулятор | `exit` |

Команды выполняются внутри эмулятора, а не через системную оболочку. Для `ls` и `cd` используются каталоги VFS, а не папки компьютера.

Неизвестные команды, неверные аргументы и недоступные пути сопровождаются сообщениями об ошибках.

### Работа с путями

Поддерживаются абсолютные и относительные пути:

- `/home/user` — абсолютный путь от корня VFS;
- `documents` — путь относительно текущего каталога;
- `.` — текущий каталог;
- `..` — родительский каталог.

Например, после `cd /home/user` команда `ls documents` покажет содержимое `/home/user/documents`, а `cd ..` выполнит переход в `/home`.

### Команда mv

Команда принимает два аргумента: исходный путь и путь назначения.

Если назначение — существующий каталог, объект перемещается в него с прежним именем. Если указан новый путь, объект переименовывается или перемещается с новым именем.

Примеры для `vfs/deep.json`:

```text
mv /home/user/documents/report.txt /report.txt
mv /report.txt /final.txt
mv /home/user /newuser
```

Предусмотрены проверки на отсутствующий источник, неверный путь назначения, существующее имя и неправильное количество аргументов.

Запрещено перемещать корень VFS и каталог внутрь самого себя. Перезапись существующих объектов не выполняется.

После переноса каталога обновляется виртуальный текущий путь, если он находился внутри перемещённого каталога. Все изменения остаются только в памяти программы.

## Виртуальная файловая система

VFS представлена деревом объектов в формате JSON:

- каталог имеет тип `directory` и поле `children` с вложенными объектами;
- файл имеет тип `file` и текстовое поле `content`.

Пример небольшой VFS:

```json
{
  "type": "directory",
  "children": {
    "note.txt": {
      "type": "file",
      "content": "Hello"
    }
  }
}
```

Перед началом работы проверяются структура и типы объектов.

В проекте подготовлены три тестовых файла:

| Файл | Содержимое |
| --- | --- |
| `vfs/minimal.json` | Пустой корневой каталог |
| `vfs/files.json` | Несколько файлов, включая пример данных в Base64 |
| `vfs/deep.json` | Вложенные каталоги `/home/user/documents` и файл `report.txt` |

В `files.json` для двоичных данных используется строка Base64 с полем `encoding`. Отдельное декодирование Base64 в текущей версии не предусмотрено.

## Стартовые скрипты

Команды можно вводить вручную или передать через параметр `--script`.

При выполнении скрипта на экране отображаются введённые команды и их результат. Если команда завершилась ошибкой, оставшиеся строки скрипта не выполняются. После такой ошибки программа возвращается в интерактивный режим.

Для проверки пятого этапа подготовлены два сценария.

**Успешный запуск:**

```powershell
python src\main.py --vfs vfs\deep.json --script scripts\stage5_startup.txt
```

Сценарий проверяет `ls`, `cd`, `echo`, `clear`, `history`, `mv` и `exit`. В том числе выполняются переименование файла и перенос каталога.

**Проверка ошибки:**

```powershell
python src\main.py --vfs vfs\deep.json --script scripts\stage5_error.txt
```

В скрипте выполняется запрещённое перемещение `/home` в `/home/user`. После сообщения об ошибке команда `echo THIS_MUST_NOT_RUN` не должна выполняться.

Для завершения интерактивного режима используется `exit`.

Также в папке `scripts` находятся сценарии предыдущих этапов и `.bat`-файлы для проверки разных параметров запуска и вариантов VFS.

## Проверка и тестирование

Автоматические тесты написаны с помощью стандартного модуля `unittest`:

- `tests/test_main.py` — проверка разбора команд, параметров запуска, VFS, основных команд и выполнения скрипта;
- `tests/test_mv.py` — проверка переименования, перемещения, обработки ошибок, переноса каталогов и неизменности исходного JSON.

Запуск всех тестов из корневой папки проекта:

```powershell
python -m unittest discover -s tests -v
```

## Особенности реализации

- Ввод разделяется на слова по пробелам. Обработка кавычек и специальных конструкций полноценной UNIX-оболочки не реализована.
- История хранится в памяти только во время текущего запуска программы.
- Изменения VFS не записываются обратно в JSON-файл.
- Реализован ограниченный набор команд; остальные команды системы не поддерживаются.
- `clear` использует системную команду очистки терминала, поэтому её поведение зависит от среды запуска.

Разработка ведётся по этапам с отдельными коммитами Git. В репозитории хранятся исходный код, тесты, сценарии запуска и документация; служебные файлы среды разработки и результаты сборки исключаются с помощью `.gitignore`.
